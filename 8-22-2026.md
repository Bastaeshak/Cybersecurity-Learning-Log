## Web Attack Detection

### SQL Injection (SQLi)

- Analyzed HTTP requests for SQL injection indicators.
- Identified payloads containing:
  - `AND 1=1`
  - `UNION ALL SELECT`
  - `information_schema.tables`
- Practiced URL decoding to expose encoded attack payloads.
- Used HTTP status codes and response sizes during analysis.
- Investigated source IP reputation using VirusTotal and AbuseIPDB.
- Learned the difference between a malicious request being processed and confirming the attacker's full objective was achieved.

### Cross-Site Scripting (XSS)

- Studied the three main XSS types:
  - Reflected XSS
  - Stored XSS
  - DOM-Based XSS
- Identified XSS indicators such as:
  - `<script>`
  - `alert()`
  - `javascript`
- Investigated an XSS SOC alert from initial detection through escalation.
- Correlated HTTP activity with endpoint, browser, terminal, and network telemetry.
- Learned that seeing an XSS payload does not automatically prove JavaScript successfully executed.

### Command Injection

- Learned how unsanitized web input can lead to operating-system command execution.
- Identified commands including:
  - `ls`
  - `whoami`
  - `uname`
  - `cat /etc/passwd`
  - `cat /etc/shadow`
- Investigated a **successful command injection attack**.
- Correlated malicious HTTP requests with endpoint terminal and process activity.
- Confirmed command execution based on matching endpoint activity around the alert timeframe.
- Practiced making a containment decision after confirming host-level execution.
- Investigated a second command injection alert that turned out to be a **False Positive**.
- Determined the detection rule matched `ls` inside the legitimate search term `skills`.

### Insecure Direct Object Reference (IDOR)

- Learned how IDOR results from improper authorization controls.
- Practiced identifying suspicious object enumeration patterns such as:

```text
?id=1
?id=2
?id=3
?id=4
```

- Learned to analyze:
  - Request frequency
  - Sequential object IDs
  - User-Agent information
  - HTTP response codes
  - Response sizes
- Learned why IDOR can be harder to detect because individual requests may look legitimate.

Investigated an external XSS attempt targeting an internal web server and reviewed endpoint telemetry for evidence of compromise.

### SOC168 — Whoami Command Detected in Request Body
**Verdict: True Positive**

Confirmed successful command injection by correlating the HTTP attack with endpoint execution:

```text
ls
whoami
uname
cat /etc/passwd
cat /etc/shadow
```

The affected web server was contained and the incident was escalated.

### SOC167 — LS Command Detected in Requested URL
**Verdict: False Positive**

The detection rule identified `ls` inside:

```text
skills
```

Browser and network history confirmed legitimate LetsDefend browsing with no corresponding malicious command execution.

## Key Takeaway

Today I combined **CySA+ studying with hands-on SOC practice**, reinforcing the concepts I am studying by applying them to actual alert investigations.

The biggest lesson was that **an alert is only the beginning of an investigation**. I practiced following the evidence from:

**Alert → HTTP Request → Network Activity → Endpoint Evidence → Timeline → Verdict → Response**

I also saw how the same type of detection can represent a real attack in one case and a false positive in another, reinforcing the importance of context, correlation, and evidence during SOC triage.
